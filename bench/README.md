# Benchmarks

Every number must be read with its `runner` block and `adapterVersion`. Shared-machine and unpinned runs do not verify the ingest latency objective. The scripts load a built directory by file URL. Run `pnpm build` first; stale builds are rejected.

| Command | Measures |
| --- | --- |
| `pnpm bench:selfcheck` | Protocol, accounting, schema and gate correctness |
| `pnpm bench:openloop --dist dist` | Intended-time ingest latency, throughput, CPU, scheduler lag and a separate no-op floor |
| `pnpm bench:latency --dist dist --samples 200` | Flush-to-judge and judge-to-sink segments, idle or with `--load 50000` |
| `pnpm bench:stores --dist dist --store sqlite` | Group commits, commit latency, bytes and CPU per event |
| `pnpm bench:alloc --dist dist --crosscheck` | Isolated reducer and end-to-end allocation cells, checked against heap sampling |
| `pnpm bench:suite --dist dist --out-dir bench/reports` | All measurements; `--quick` shortens runs |
| `pnpm bench:validate bench/reports/*.jsonl` | Strict report validation |
| `pnpm bench:gates bench/reports/*.jsonl` | The five SLO gates |
| `pnpm test:oracle` | Frozen reducer and engine behavior |

Reports are JSONL, validated against [lib/schema.mjs](lib/schema.mjs). Use `--out file.jsonl` to append them. No-op runs use the same intended schedule as the engine. Histograms count latency from intended send time, including missed credit and generator stalls. Stream ack frames carry rejected line indexes. A rejected line stays out of both the intended-time and engine latency histograms and counts in `rejected`. A line still unacknowledged when the drain timer fires is charged from its intended time to that moment and counts in `failed`. `--mix tape --tapes file.json` accepts `{ "tapes": [{ "name": "sample", "events": [{ "t": 0, "kind": "continuous" }] }] }`; supply tapes locally.

Measurement starts when the target parses the first line after warm-up, so the generator never pauses at the boundary. Durable bytes are the lengths of the strings each write binds: every string parameter of a write statement or command on the state port (the record JSON and its keys, never a Redis script body), and the serialized inputs, snapshot and decision rows on the scope port. Bench events are ASCII, so the lengths are bytes. Durable CPU is the attend process's own; database server CPU is not included.

SQLite modes report journal mode and synchronous separately. Postgres reports `synchronous_commit`; Redis reports both AOF enablement and `appendfsync`. `ATTEND_POSTGRES_URL` and `ATTEND_REDIS_URL` select external services. The suite skips either service if its URL is absent. Each durable run creates and removes its own tables, keys or database file.

The open-loop gates count only runs over at least 1000 scopes with at least 59.9 measured seconds. SLO 1 requires at least three runs at 50000 for each of `continuous` and `realistic`, all achieving at least 99.9% of the target rate, with flat first-to-last p50, no failed or rejected lines, and at most one core. Flat means the last p50 is at most twice the first plus 100 microseconds. Its knee is the highest passing rate without the CPU condition. SLO 2 requires at least three pinned runs with usable no-op floors per mix and rate at 10000, 30000 and 50000. A usable floor has no failed or rejected lines and achieves at least 99.9% of the target rate. Every such run must achieve at least 99.9% of the target rate, have flat p50 and no failed or rejected lines, and have both engine p99 and end-to-end p99 minus no-op p99 at most 100 microseconds. Too few pinned runs with usable floors means `not verified`.

SLO 3 requires both complete W x S grids from the same build, within 20% of row and column medians, and at most 1536 bytes per end-to-end event at S=500. Allocation cells have no size floor. SLO 4 requires 20 cells: five modes times two workloads times two windows. The modes are in-thread SQLite WAL/NORMAL, WAL/FULL and DELETE/FULL, Postgres `synchronous_commit=on`, and Redis `appendonly=true` with any `appendfsync`. The workloads require at least 200 scopes with at least 700 events each, and at least 1000 scopes with at least 140,000 total events. Each needs reports at exactly W=50 and W=250. Undersized reports are ignored and counted in `info.undersized`. Every sized report, including other modes, must show more than one event per commit at 1000 events/s or more, and at most four times the event bytes written. Below 1000 events/s, grouping is `not verified`. SLO 5 requires a memory idle report, a memory report targeting at least 50000 events/s, and one report per durable store. Usable reports have at least 200 probes and none failed. Any matching report with failed probes is `not met`. Every loaded report must achieve at least 99.9% of its target rate over at least 1000 scopes. Non-judge p99 must be at most 2 ms idle on memory, 10 ms on loaded memory, or twice commit p99 plus 2 ms on durable stores; missing commit latency is `not verified`. The subscriber segment needs a measurement from a usable report. `latency.mjs` emits its report and exits 1 if any probe failed or it collected fewer than `--samples`, which defaults to 200 and sets both the idle count and loaded minimum. Missing evidence yields `not verified`; a failed gate yields `not met` and exit code 1.

On Linux, use `taskset -c <generator cores>` around the command and `--target-cpus <different cores>` for the target. Both affinity sets must be proper subsets of the online CPUs and disjoint to report a pinned open-loop run. The workflow takes these lists from `ATTEND_BENCH_GENERATOR_CPUS` and `ATTEND_BENCH_TARGET_CPUS`. `ATTEND_PERF_RUNS_ON` is the dedicated runner label array in JSON. Outside Linux, CPU pinning is unavailable.
